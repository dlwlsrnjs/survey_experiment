# 서베이 논문과 실험 설계의 연결

이 문서는 진행 중인 서베이 **Roles of Large Language Models in Multimodal Jailbreaking: A Survey**의 문제의식이 왜 이 저장소의 실험으로 이어지는지 설명한다. 설치법보다 먼저, 연구 질문·설계 선택·측정값·주장 범위를 이해하려는 독자를 위한 문서다.

근거 문서는 다음 두 파일이다.

- [진행 중 서베이 논문](../서베이논문%28진행중%29.pdf)
- [보조 모델 작업 과정 실험안](../VLM_Survey_Auxiliary_Model_Experiment_Plan_KO.pdf)

## 1. 한 문장으로 보는 연구 의도

**최종 공격 성공률만 비교하지 않고, 멀티모달 공격 절차 안에서 보조 모델이 받은 정보, 만든 중간 산출물, 그 산출물을 사용한 다음 단계를 실제 호출 단위로 추적하여 역할별 거부·품질·오류 전파·피드백과 경험의 효과·비용을 비교한다.**

이 실험은 새로운 공격의 최고 ASR을 달성하려는 벤치마크가 아니다. 서베이가 문헌에서 찾아낸 역할 분류와 정보 흐름을 통제된 조건에서 측정 가능하게 만드는 연구 도구다.

## 2. 서베이가 제기한 문제

### 2.1 최종 입력만 보면 참여 모델의 기여가 가려진다

FigStep, HADES, IDEATOR는 모두 최종적으로 이미지–텍스트 입력을 표적 VLM에 전달할 수 있지만, 참여 모델이 보는 증거와 개입 시점은 다르다. FigStep의 작성 모델은 렌더링된 이미지를 보지 않고, HADES는 표적 질의 전에 이미지 캡션과 평가를 이용하며, IDEATOR는 생성 이미지와 표적 응답을 보고 다음 시도를 수정한다. 서베이는 따라서 모델이 **무엇을 받고, 무엇을 출력하며, 어느 연산이 그 출력을 소비하는지** 추적해야 한다고 주장한다(서베이 PDF pp. 1–2).

이 저장소는 이 세 항목을 로그 계약으로 바꾼다.

| 서베이의 분석 질문 | 저장소에서 남기는 증거 |
|---|---|
| 모델이 무엇을 받았는가? | 실제 system/user 메시지, 이미지 경로와 SHA-256, 제공한 피드백·경험 ID |
| 모델이 무엇을 만들었는가? | 원문 응답, 파싱된 역할별 JSON, 거부·형식 검사, 생성 이미지 |
| 어디에 사용되었는가? | `next_consumer`, 렌더러/T2I 결과, 평가·수정 입력, 검색 계획 |
| 어떤 비용이 들었는가? | 호출 수, latency, prompt/completion token, 표적 질의 예산 |

비공개 chain-of-thought를 복원하는 것이 아니라, 연구자가 사전에 요청한 관찰 가능한 산출물과 실제 handoff를 분석한다.

### 2.2 네 역할은 이름이 아니라 정보 흐름으로 정의된다

서베이는 44개 연구의 모델 참여를 `Generation`, `Planning`, `Evaluation`, `Reuse`로 분류한다. 한 호출이 여러 역할을 수행할 수도 있고, 같은 역할도 여러 호출에 나뉠 수 있으므로 역할은 에이전트 이름이 아니라 입력·출력·후속 사용으로 판정한다(서베이 PDF pp. 1, 3–4).

이 저장소의 네 실험 역할은 다음과 대응한다.

| 서베이 역할 | 저장소 역할 | 핵심 질문 | 관측 가능한 중간 산출물 |
|---|---|---|---|
| Generation | `generation` | 텍스트 목표를 시각 입력 구성 요소로 바꿀 수 있는가? | 거부, 렌더링 문장, 장면 설명, 의미 보존, 렌더러/T2I 결과 |
| Planning | `observation_planning` | 실제 이미지 근거를 사용해 허용된 행동 안에서 계획하는가? | 시각 근거, OCR, 추론, 계획 단계, 도구 호출 |
| Evaluation | `evaluation_revision` | 후보와 선택적 표적 응답을 구분해 평가하고 개선하는가? | 후보 거부, 이해/이행 판정, 품질, 오류 유형, 수정안 |
| Reuse | `experience_use` | 이전 피드백과 다른 개발 사례의 경험을 현재 후보에 적용하는가? | 제공·사용 경험 ID, 적용 설명, 다음 후보, goal drift |

Generation 내부의 시각 입력용 내용과 표적 텍스트용 내용을 구분한다는 서베이의 `G_i/G_t` 정의도 유지한다. 현재 공통 실험의 `generation`은 주로 `G_i`에 해당하며, 표적 텍스트 생성까지 포괄하는 일반적 `G_t` 성능을 대표한다고 주장하지 않는다.

### 2.3 서로 다른 논문의 ASR은 역할 효과의 직접 비교가 아니다

서베이는 공격 결과가 각 연구의 표적 모델, 요청 집합, 이미지 재구성, judge와 집계 규칙에 의존하므로 서로 다른 연구의 성공률을 하나의 순위처럼 합치지 않는다(서베이 PDF p. 3). Table 7의 수치도 개별 연구 내부 비교이며 행 사이의 순위가 아니라고 명시한다(서베이 PDF p. 14).

그래서 이 저장소는 두 실행 트랙을 분리한다.

| 트랙 | 고정하는 것 | 바꾸는 것 | 답할 수 있는 질문 |
|---|---|---|---|
| 공통 통제 실험 | manifest, 역할 지시, 출력 schema, 예산, 공통 SDXL, 평가 규칙 | 역할 또는 보조 모델 | 같은 계약에서 역할 수행 차이가 나타나는가? |
| 원형 충실도 실행 | 공개 구현의 prompt, 정보 흐름, 기법별 T2I 설정 | 기법이 정한 역할 경로 | 공개 절차의 handoff를 따를 때 어떤 중간 산출물이 생기는가? |

공통 실험은 인과적 분리를 돕지만 원 기법 전체를 재현하지 않는다. 원형 충실도 실행은 생태적 타당도를 높이지만 기법마다 구성 요소가 달라 단순한 모델 우열 비교에 쓰지 않는다. 두 트랙을 함께 두는 이유는 **통제 가능성**과 **원 절차 충실도**를 한 결과로 혼합하지 않기 위해서다.

## 3. 왜 이 다섯 기법을 연결했는가

서베이의 Figure 4와 Table 5는 공격 절차에서 모델 출력이 다음 단계로 이동하는 방식을 보여준다(서베이 PDF pp. 12–13). 실험안은 이 중 공개 구현과 역할 구분이 분명한 사례를 선택한다(실험안 PDF p. 2).

| 기법 | 실험에서 가져오는 역할 증거 | 선택 이유 | 이 저장소에서의 경계 |
|---|---|---|---|
| FigStep | 문장 재구성 → 고정 타이포그래피 렌더러 | 작성 모델과 결정적 도구의 성공/실패를 분리하기 좋음 | 전체 SafeBench 재현이 아니라 공통 HarmBench 목표에 대한 작성 역할 |
| HADES | 캡션·평가 → diffusion prompt 수정 → 이미지 | 표적 질의 전 이미지 평가와 반복 개선의 흐름이 명확함 | 공통 실험은 SDXL, 원형 충실도 트랙만 PixArt 사용 |
| HIMRD | 결과 판정 → prefix/suffix 또는 장면 prompt 재작성 | Evaluation이 다음 Generation을 바꾸는 경로를 보기 좋음 | 실제 표적 응답이 없는 실행에서는 최종 공격 성공을 주장하지 않음 |
| MM-Plan | 이미지 관찰 → 계획 → 제한된 행동 실행 | Planning의 시각 근거와 도구 제약을 구조화하기 좋음 | 원 GRPO 체크포인트 재현이 아니라 inference-only 역할 비교 |
| MemJack | 피드백·검색 경험 → 다음 후보 | Reuse를 피드백과 분리하고 무작위 경험 대조군을 만들 수 있음 | 공개 train 궤적을 고정 경험 은행으로 사용하며 eval/test 누출 금지 |

세부적인 보존·변형 범위는 [공개 구현 및 논문 설정 대응표](PROTOCOL_ADHERENCE_KO.md)에 있다.

## 4. 문헌의 관찰을 어떤 실험 질문으로 바꾸는가

### RQ1. 역할에 따라 보조 모델의 거부와 작업 품질이 달라지는가?

서베이는 참여 모델이 최종 금지 응답을 직접 작성하지 않더라도 계획, 평가, 중간 작성으로 공격을 진전시킬 수 있다고 지적한다(서베이 PDF pp. 1–2). 따라서 최종 응답 안전성만 검사하면 보조 능력과 거부 지점을 놓칠 수 있다.

같은 32B 모델에 네 역할의 명시적 계약을 부여하고 다음을 분리해 측정한다.

- 정책·안전 이유의 수행 거부
- 파싱·형식 유효성
- 비거부 산출물의 0/1/2 품질
- 다음 단계에 그대로 전달 가능한 2점 산출물 비율
- API 오류, 도구 오류, 미도달

거부를 품질 0에 합치지 않는 이유는 “모델이 시도했으나 실패함”과 “역할 수행 자체를 거부함”이 서로 다른 안전·신뢰성 현상이기 때문이다(실험안 PDF p. 3).

### RQ2. 이미지 표현 방식이 관찰·계획에 어떤 차이를 만드는가?

MM-SafetyBench의 같은 목표에 대해 `SD`와 `SD_TYPO`를 짝으로 두고, 관찰 근거·OCR·계획 품질·거부의 목표 내 차이를 비교한다. 두 변형을 독립 표본 두 개로 세지 않고 `goal_id` 단위로 짝짓는다(실험안 PDF pp. 1, 5).

이 비교는 자연 이미지 전반의 시각 추론 성능을 뜻하지 않는다. 이미지 변형과 질문 문구가 함께 달라질 수 있으므로, 결과를 순수한 픽셀 변화의 인과 효과로 과장하지 않는다.

### RQ3. 현재 피드백과 다른 사례의 경험은 다음 후보를 개선하는가?

서베이의 문헌 비교는 경험의 양, 조직 방식, 초기화와 온라인 갱신이 서로 다른 조작임을 보여준다(서베이 PDF pp. 13–14). 이 저장소는 이를 A/B/C/C_random 네 조건으로 나눈다.

| 조건 | 현재 피드백 | 검색 경험 | 식별하려는 차이 |
|---|---:|---:|---|
| A | 없음 | 없음 | 독립 생성 기준선 |
| B | 있음 | 없음 | `B − A`: 현재 피드백 효과 |
| C | 있음 | 관련 train 경험 3개 | `C − B`: 관련 경험의 추가 효과 |
| C_random | 있음 | 개수·길이를 맞춘 무작위 train 경험 3개 | `C − C_random`: 관련성 효과 |

검색은 모델 호출 전에 `retrieval_plan.jsonl`로 동결한다. 경험 은행은 MemJack train split만 사용하고, 평가 사례의 정보가 들어오면 실행을 중단한다. 이 조작은 실험안 PDF p. 4의 피드백·경험 분리 원칙을 구현한다.

### RQ4. 중간 오류와 개선은 다음 단계와 비용에 어떻게 연결되는가?

서베이는 표적 질의가 줄어도 참여 모델 token이나 이미지 생성 비용이 늘 수 있으므로, 성공률과 표적 질의 수만으로 효율을 판단하기 어렵다고 설명한다(서베이 PDF p. 14). 따라서 이 저장소는 다음을 함께 기록한다.

- 중간 산출물의 오류 유형과 다음 소비자
- 수정 전후 품질
- 표적 질의 수와 보조 모델 호출 수
- prompt/completion token과 latency
- 이미지 생성 모델·설정·artifact SHA-256

현재 공통 runner는 `target_query_cap`을 config에 기록하지만 표적 모델 질의를 end-to-end로 수행하거나 강제하지 않는다. 따라서 현 단계 결과로 “같은 표적 질의 예산에서 최종 ASR이 개선됐다”고 주장할 수 없다.

## 5. 데이터와 비교 단위가 이렇게 정해진 이유

실험안은 HarmBench Standard의 개발 20·평가 50개 목표와 MM-SafetyBench의 개발 20·평가 50개 목표를 사용하고, MM 목표마다 `SD/SD_TYPO` 두 조건을 둔다(실험안 PDF p. 1).

| 데이터 | 역할상 쓰임 | 통계 단위 |
|---|---|---|
| HarmBench-Standard | 텍스트 목표에서 렌더링 문장·장면 설명 생성 | 목표 1개 |
| MM-SafetyBench | 이미지 관찰·계획, 후속 평가·경험 사용 | `SD/SD_TYPO`를 묶은 목표 1개 |
| MemJack 공개 train 궤적 | 평가와 분리된 경험 은행 | 경험 레코드, 검색 후에는 목표별 고정 목록 |

기본키는 `(experiment_id, role, condition, repeat, condition_id)`다. 반복 실행과 이미지 변형을 독립 표본처럼 부풀리지 않고 목표 단위 paired 분석을 사용한다.

## 6. 계획된 산출물과 분석

공통 전체 실행은 일반 역할 300호출과 경험 조건 1,800호출, 총 2,100호출로 계획되어 있다. 이 수는 실험 설계의 계획값이며 완료 결과가 아니다.

1. 실행 건전성: 오류, 누락, 형식 유효성
2. 역할별 거부와 비거부 품질 분포
3. `SD_TYPO − SD`의 목표 단위 paired bootstrap
4. `B − A`, `C − B`, `C − C_random`의 동일 목표·동일 반복 대비
5. 제공한 경험과 사용했다고 보고한 경험의 일치
6. 역할별 token, latency와 도구 비용
7. 모델명을 가린 두 평가자의 독립 평정과 조정본
8. 성공 사례만 고르지 않는 사전 정의 오류 유형 기반 질적 사례 8건

세부 분석법과 완료 조건은 [실험 설정 및 중간작업 분석 계획](EXPERIMENT_AND_INTERMEDIATE_ANALYSIS_KO.md)에 있다.

## 7. 이 실험으로 말할 수 있는 것과 없는 것

| 말할 수 있는 것 | 현재 설계만으로 말할 수 없는 것 |
|---|---|
| 고정 입력·계약에서 역할별 거부와 산출물 품질 차이 | VLM 탈옥 기법 전체의 보편적 성능 순위 |
| 관찰 가능한 중간 산출물의 오류와 handoff 경로 | 모델의 비공개 chain-of-thought |
| 현재 피드백·관련 경험·무작위 문맥의 조건부 차이 | 검색 또는 경험의 일반적인 인과 효과 |
| 해당 SD/SD_TYPO 표본의 목표 내 차이 | 자연 이미지·도면 전반의 시각 추론 능력 |
| 실행한 모델·revision·prompt·예산에서의 결과 | 원 논문이 보고한 ASR의 완전 재현 |
| 원형 충실도 runner가 보존한 prompt와 정보 흐름 | 전체 원 구현과 동일한 end-to-end 공격 성공률 |

최종 결과라고 부르려면 계획 호출 완료 또는 누락 사유, provenance, 두 평가자의 독립 평정, 평가자 간 신뢰도, 조건별 분모와 신뢰구간이 필요하다. 현재 부분 실행과 자동 평정은 예비 운영 결과일 뿐이다.
